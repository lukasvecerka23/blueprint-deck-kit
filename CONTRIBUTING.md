# Contributing

Thanks for helping. Issues, examples, translations of the UI labels and fixes are all welcome.

## How the repository fits together

```
skill/blueprint-deck/        what users install (the agent skill)
  SKILL.md                   the instructions the agent follows
  blueprint-deck.html        the engine with an empty data block (generated, don't edit)
  reference/ templates/      format reference, style guide, icons, config template, example
  tools/check.mjs            optional command-line check (Node 18+)
engine/src/                  the engine's source
  core.js                    defaults, layout, validation (no DOM; also used by check.mjs)
  render.js                  draws and runs one diagram
  boot.js                    loads the data, saves edits, several diagrams, preview hook
  editor.js, editor.css      the editor (press E)
  engine.css                 styles and theme tokens
  icons.js                   Lucide icons (generated by dev/make-icons.mjs)
  template.html              the page the parts are put into
configurator/                the form that writes diagram.config.yaml and the prompt
site/                        the website (Astro)
examples/                    example diagrams (each one HTML file + its config and report)
dev/                         maintainer scripts
```

## Working on the engine

You need Node 18+ (users don't; only contributors).

```bash
node dev/assemble.mjs                                  # engine/src → skill/blueprint-deck/blueprint-deck.html
node dev/assemble.mjs --upgrade examples/*/index.html  # put the new engine into the examples (keeps their data)
node skill/blueprint-deck/tools/check.mjs examples/acme/index.html --explain
python3 -m http.server 8765                            # then open http://localhost:8765/examples/acme/index.html
```

Commit the regenerated `blueprint-deck.html` and examples together with your source change; CI checks they match.
Open a page with `#check` (e.g. `index.html#tour=3&check`) to run the screen checks, or press E → Check.

Icons: add names to `dev/icon-list.txt`, then `npm pack lucide-static` somewhere outside the repo and run
`node dev/make-icons.mjs <path to the unpacked package>`.

Ground rules for the engine:
- It must stay one self-contained file that works offline from `file://`: no network requests, no CDN, no build tools
  needed by users.
- New diagram features go into the data format (`reference/spec.md`), with defaults in `core.js`, validation for
  mistakes an agent is likely to make, and a line in the style guide if it changes how diagrams should be written.
- Keep old data working: rename with an alias rather than breaking existing files.

## Releasing

The version lives in one place: `VERSION` in `engine/src/core.js` (`dev/assemble.mjs` writes it into the engine,
`skill/blueprint-deck/VERSION` and, through the site build, `version.json` on the website).

1. Bump `VERSION` (minor for features, major if old diagrams would need an upgrade) and add a `## x.y.z (date)`
   section at the top of `CHANGELOG.md`.
2. `node dev/assemble.mjs && node dev/assemble.mjs --upgrade examples/*/index.html`, commit, push.
3. `git tag vx.y.z && git push --tags`: the Release workflow checks everything and publishes a GitHub release with
   the notes and the skill archives. The website (and so the install command and the update check) serves `main`.

## Working on the skill

The skill is plain Markdown. If an agent got something wrong, the best fix is usually a sharper rule in `SKILL.md` or
the style guide, plus a check in `core.js` that catches it. Test changes by generating a diagram with at least one
agent and say which in the pull request.

## Pull requests
